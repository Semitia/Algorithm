# 3090. 每个字符最多出现两次的最长子字符串

## 方法一：枚举窗口长度

字符串长度最大只有 `100`，所以可以直接枚举所有窗口：

- 外层循环枚举窗口长度；
- 内层循环枚举该长度下窗口的起点；
- 使用长度为 `26` 的数组记录窗口内每个字母的出现次数。

对于一种新的窗口长度，先统计第一个窗口。之后窗口每向右滑动一格，只需将离开窗口的字符计数减一，再将新进入窗口的字符计数加一，不需要重新统计整个窗口。

每次检查 `26` 个计数是否都不超过 `2`。如果当前窗口合法，就用它的长度更新答案。

时间复杂度为 `O(26n²)`，因为字符集大小固定，也可以记作 `O(n²)`；空间复杂度为 `O(1)`。

对应提交代码为 `3090.cpp`。

## 方法二：可变长滑动窗口

这个方法也叫“双指针”。它不是凭空出现的，而是从方法一继续消除重复工作得到的。

### 方法一重复枚举了什么

方法一分别检查长度为 `1、2、3……` 的窗口，但我们真正关心的是：

> 对于每一个右端点 `right`，以它结尾的最长合法窗口是什么？

如果能回答这个问题，就已经考虑了所有可能成为答案的窗口，没有必要再枚举窗口长度。

用 `left` 表示当前窗口的左端点，并让 `right` 从左向右遍历字符串。加入 `s[right]` 后有两种情况：

1. 新字符在窗口内出现不超过两次，窗口仍然合法；
2. 新字符出现了三次，窗口不合法。

第二种情况下，固定当前的 `right`，想让窗口重新合法，只能不断右移 `left`，从窗口左边删除字符，直到新字符的出现次数回到两次。

恢复合法后，`[left, right]` 就是以 `right` 结尾的最长合法窗口。更靠左的窗口仍然包含该字符的三次出现，不合法；更靠右的窗口虽然合法，但一定更短。

因此，每次恢复合法后直接更新答案即可。

### 为什么只检查新加入的字符

加入 `s[right]` 之前，窗口本来是合法的。加入一个字符时，只有这个字符的计数增加了，其他字符不可能突然超过两次。因此只需判断：

```cpp
count[s[right] - 'a'] > 2
```

### 为什么 `while` 不会让复杂度变成 `O(n²)`

虽然代码中是 `for` 里面套着 `while`，但 `right` 和 `left` 都只会从左向右移动，不会回退：

- `right` 最多移动 `n` 次；
- `left` 在整个程序中也最多移动 `n` 次。

所以总移动次数不超过 `2n`，时间复杂度为 `O(n)`，空间复杂度为 `O(1)`。这种分析叫作均摊分析。

```cpp
#include <algorithm>
#include <array>
#include <string>

class Solution {
public:
    int maximumLengthSubstring(const std::string& s) {
        std::array<int, 26> count{};
        int left = 0;
        int answer = 0;

        for (int right = 0; right < static_cast<int>(s.size()); ++right) {
            int index = s[right] - 'a';
            ++count[index];

            while (count[index] > 2) {
                --count[s[left] - 'a'];
                ++left;
            }

            answer = std::max(answer, right - left + 1);
        }

        return answer;
    }
};
```

## 怎样识别这类题

看到下面几个特征时，可以尝试可变长滑动窗口：

1. 题目要求连续的子数组或子字符串；
2. 需要寻找最长或最短的合法区间；
3. 右端加入元素后，可以快速判断窗口是否合法；
4. 窗口不合法时，删除左端元素能够逐步恢复合法性；
5. 两个边界都只需要单向移动，不需要回退。

这道题最重要的经验不是记住代码，而是把“枚举每一种长度”改写成“固定右端点，维护最长的合法后缀”。这一步正是从 `O(n²)` 枚举过渡到 `O(n)` 滑动窗口的关键。
