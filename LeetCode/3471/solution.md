# 3471. 找出最大的几近缺失整数

## 滑动窗口 + 活跃区间延迟结算

用 `windowFrequency[x]` 维护数字 `x` 在当前窗口内出现了多少次。窗口每向右滑动一格，只需删除左端元素并加入右端元素，这部分确实是 `O(1)`。

不过，`windowCount[x]` 统计的是“有多少个窗口包含 `x`”，不能只在 `x` 滑入窗口时加一。假如 `x` 留在窗口中没有成为本次的出入元素，新窗口仍然包含它，也应当计数。

为了避免每次遍历整个窗口或所有可能的数字，可以延迟结算：

- `activeSince[x]` 表示从哪个窗口起点开始，`x` 一直存在于窗口中；
- 当 `windowFrequency[x]` 从正数变成 `0` 时，说明这段连续出现结束；
- 若当前新窗口的起点是 `start`，那么这段区间覆盖了
  `start - activeSince[x]` 个窗口，一次性加进 `windowCount[x]`；
- 所有窗口滑完后，再结算仍留在最后一个窗口中的数字。

同一个数字在窗口中出现多次时，只有计数从 `0` 变成 `1` 或从 `1` 变成 `0` 才代表其活跃区间开始或结束，因此不会把同一窗口重复计算。

最后从 `50` 到 `0` 倒序查找第一个 `windowCount[x] == 1` 的数字即可。

时间复杂度为 `O(n + V)`，其中 `V = 51`；空间复杂度为 `O(V)`。由于题目规定 `0 <= nums[i] <= 50`，二者也可以分别视为 `O(n)` 和 `O(1)`。

对应提交代码为 `3471.cpp`。

## 边界观察

还可以不模拟窗口，直接讨论 `k` 和数组长度 `n` 的关系。

### `k == n`

整个数组就是唯一的长度为 `k` 的子数组，所以数组中的每个数字都只出现在这一个窗口中。答案是数组最大值。

### `k == 1`

每个窗口只有一个元素。一个数字出现在多少个窗口中，就等于它在数组中的出现次数，因此答案是全局只出现一次的最大数字。

### `1 < k < n`

数组第一个位置只属于起点为 `0` 的窗口，最后一个位置只属于起点为 `n - k` 的窗口；任何中间位置都至少属于两个长度为 `k` 的窗口。

因此，几近缺失整数只能是 `nums.front()` 或 `nums.back()`。但候选数字如果还在数组其他位置出现过，其覆盖的窗口也不止一个，所以它还必须在整个数组中只出现一次。

统计所有数字的出现次数，再检查首尾两个候选即可。

时间复杂度为 `O(n + V)`，其中 `V = 51`；空间复杂度为 `O(V)`。由于值域固定，也可以分别记作 `O(n)` 和 `O(1)`。

对应提交代码为 `3471_boundary.cpp`。

## 复盘

最初的方向是正确的：固定长度的窗口滑动时，窗口内容的频率只需修改滑出和滑入的两个元素。容易混淆的地方是，题目要统计的不是元素进入窗口的次数，而是包含该元素的窗口数。窗口中没有发生出入的元素也进入了一个新的子数组，仍然需要累计。

如果每个窗口都扫描一次其中的 `k` 个元素，复杂度是 `O(nk)`；如果每次扫描 `0..50`，利用值域固定也已经足够通过，并且可以写作 `O(51n) = O(n)`。本解法进一步利用一个元素是否存在只在频率跨过 `0` 时发生变化，把连续多个窗口的贡献合并结算，从而实现真正的每次滑动 `O(1)`。

题目标签写“哈希表”是因为一般情况下需要建立“值到计数”的映射，并不代表必须使用 `unordered_map`。本题值域只有 `0..50`，定长数组更直接，也避免了哈希开销。

进一步复盘后发现，这道题虽然可以用滑动窗口准确模拟，但“一个位置会被多少个定长窗口覆盖”才是更直接的突破口。先讨论 `k == 1`、`k == n` 和中间情况，就能把一般的窗口统计缩小为首尾两个候选。简单题中的数据范围不仅决定使用数组还是哈希表，参数的边界关系也可能直接改变问题结构。
